## 一、 八维度综合加权评分模型

我们在每一家机场的综合天梯排名评定中，严格按照以下八大工程维度进行权重分配：

| 评价维度 | 评分权重 | 核心评估指标 | 检测工具与采集策略 |
| :--- | :---: | :--- | :--- |
| **晚高峰丢包与稳定性** | **25%** | 20:30~22:30 连续 100 次采样丢包率 | MTR 路由追踪 + 持续心跳监控 (`Loss% <= 0.1%` 满分) |
| **单线程持续下载吞吐** | **20%** | 连续拉取 1GB 测试包平均速率 | `curl` / `iperf3` 单线程长期压测，排除 5 秒突发峰值 |
| **物理专线与电路资质** | **15%** | 是否真正在骨干网内采用 IEPL / IPLC 专线 | 检查入口跳点 ASN 与海底光缆过境特征 |
| **AI 与流媒体解锁纯净度**| **15%** | ChatGPT / Claude / Netflix 原生解锁率 | 自动化脚本 `check.unlock.media` + Scamalytics 评分 |
| **抖动偏差与游戏兼容性**| **10%** | 往返延迟离散度 (Jitter) 与 NAT 映射类型 | 验证是否支持 Full Cone NAT (NAT 1) 及 UDP 转发 |
| **品牌运营年限与跑路免疫**| **10%** | 历史存续年限、售后工单响应、收款合规性 | 排查同源站群、TG 异常禁言与资金盘折价信号 |
| **客户端适配与易用性** | **5%** | 原生订阅格式下发、倍率标示透明度 | 测试 Clash Verge Rev, Sing-box, Shadowrocket 兼容性 |

## 二、 自动化采集测试流 (MAI-TEST-BOT 2.0)

我们的后台自动化调度系统每晚准时启动测试工作流：

```
[20:30 启动压测容器] ──> [同步全站 42 家机场最新订阅配置]
         │
         ▼
[阶段一：MTR 丢包率探测] ── 向港/日/新/美主力节点发送 100 组数据包，淘汰丢包 > 5% 节点
         │
         ▼
[阶段二：单线程大文件吞吐] ── 禁用并发加速，抓取 Cloudflare 真实海外冷数据文件，记录均速
         │
         ▼
[阶段三：AI 与流媒体校验] ── 发起 OpenAI / Netflix 原生环境探测，标记 1020 与自制剧降权节点
         │
         ▼
[数据写入持久化时序库] ── 剥离异常离群极值，生成 7 日与 30 日平滑可用率报表
```

## 三、 严格的数据状态分级标识规则

为了确保每一位读者清晰分辨数据的可信来源，本站对每一项收录品牌强制打上三重状态印记：

1. **实测验证 (Measured)**：实验室采购了商业测试账号并在珠海联通 9Gbps 物理机房完成了晚高峰自动化闭环采样，具备完整速率图表与丢包记录；
2. **品牌资料 (Vendor)**：服务商向实验室提供了基础设施架构与标准资费参数，尚处于观察期内，待排期完成多地交叉全量复测；
3. **历史存档 (Historical Data)**：早期行业经典老牌或小众节点资料记录，已标明历史测速时间，供溯源参考，暂不推荐作为首选主力。

## 四、 独立性与数据客观承诺

* **拒绝任何付费买榜或篡改评分**：任何服务商提供的合作佣金或测试资金，绝对不会影响其在实验室测评天梯中的丢包率、延迟及欺诈评分输出；
